Glyph Cube

Spin the cube, find the groove
Live · Oct 2026

A pocket beat machine built as a metallic 3D cube you spin, rendered with SceneKit. Each face is an instrument: a drum sequencer, a melody/piano roll, and a sample slicer for vocal chops. You spin the cube to switch between them. The glyph visuals have an edge glow.

  • Version 1.0 went live October 16, 2026. 1.0.1 is in App Store review.
  • 1.0.2 (in testing) is a performance pass, measured on an iPhone with a Release build. A main-thread stall went from about 1362 ms to about 1.3 ms per run, and a row-sync cost went from about 380 ms to about 6 ms.
  • I added a low-graphics mode that cuts pixels drawn from 3.79 MP to 1.68 MP. Memory stayed flat in soak tests.
Role: Solo developer and designer

DUET Synth

Two players, one device
Live · Sep 2026

A two-player synth. The left and right halves of the screen are separate instruments, so two people can play together, have a click-fight, or hunt for notes. It's free, ad-supported, and styled amber on black.

  • Apple rejected the first submission. To get it approved, I added a Remove Ads in-app purchase and a first-open tutorial, and I rewrote the store listing.
  • I wrote a custom DSP synth engine on AVFoundation/AVAudioEngine, with CoreHaptics feedback and XCTest unit tests.
  • I set up Google Mobile Ads (AdMob) alongside a StoreKit Remove Ads purchase.
  • An Android version is built and in Google Play setup.

Tape Eater

Glitchy, broken-tape video effects
Live · Sep 2026

A video-effects toy that pushes, smears, and scrambles camera or Photos footage until it looks like damaged VHS or a crashing file. It also has a second thermal/smear look called Silt mode. You can save a clip or a still, and everything stays on the device.

  • The effects run on the GPU with Metal and MetalKit. It's free, with no ads, and all processing happens on the device.
  • Live controls for deep tweaking, plus one-tap presets.

How I work

I use AI-directed development. I run several AI coding agents in parallel, mainly the Claude Code CLI. I decide what gets built, and I'm responsible for what ships.

Brief

I break the work into small, clear tasks. Each brief spells out the goal, the limits, and what "done" means.

Parallelize

Each agent works on its own git branch or worktree, so separate features and fixes can move forward at once without stepping on each other.

Review

I read every diff before merging. I keep the changes that are right and send back the ones that aren't.

Verify on device

I test on real iPhones, using Release builds, Instruments profiling, and devicectl. I trust the numbers I measure on the device, not the ones that look good in the simulator.

Example: For Glyph Cube 1.0.2, I profiled a Release build on an iPhone and found a main-thread stall. After the fix, it went from about 1362 ms to about 1.3 ms per run. I confirmed the fix with memory soak tests before it went to testing. This is the workflow I want to bring to a team that's adopting AI-assisted development.
